cheesedb is starting (preview: sessions approved by a person are not built
yet; keep the server inside a trusted cluster).

1. Trust the server's certificate:
{{- if eq .Values.tls.mode "selfSigned" }}
   kubectl get secret -n {{ .Release.Namespace }} {{ include "cheesedb.tlsSecret" . }} -o jsonpath='{.data.ca\.crt}' | base64 -d > cheesedb-ca.crt
{{- else }}
   use the certificate authority that issued the Secret {{ include "cheesedb.tlsSecret" . }}.
{{- end }}

2. The admin token (creates and deletes agents):
{{- if or .Values.admin.keyHash .Values.admin.existingSecret }}
   the token whose hash you gave: ADMIN=<that token>
{{- else }}
   ADMIN=$(kubectl get secret -n {{ .Release.Namespace }} {{ include "cheesedb.adminSecret" . }} -o jsonpath='{.data.admin-token}' | base64 -d)
{{- end }}

3. Try it from your machine:
   kubectl port-forward -n {{ .Release.Namespace }} svc/{{ include "cheesedb.fullname" . }} 7700:{{ .Values.service.port }}
   curl --cacert cheesedb-ca.crt https://localhost:7700/v1/health
   printf 'Authorization: Bearer %s\n' "$ADMIN" | curl --cacert cheesedb-ca.crt -H @- -d '{"name":"alice"}' https://localhost:7700/v1/admin/agents

Inside the cluster, programs call https://{{ include "cheesedb.fullname" . }}.{{ .Release.Namespace }}.svc:{{ .Values.service.port }}
and trust the same certificate.
{{- if not .Values.networkPolicy.enabled }}

WARNING: networkPolicy is off, so every pod in the cluster can reach the
server. Turn it on and list your agents' pods:
  --set networkPolicy.enabled=true --set networkPolicy.from[0].podSelector.matchLabels.app=<your-agent>
{{- end }}
{{- if ne .Values.service.type "ClusterIP" }}

WARNING: service.type is {{ .Values.service.type }}, so the server can be reached from
outside the cluster. Keep it ClusterIP unless you need that.
{{- end }}
